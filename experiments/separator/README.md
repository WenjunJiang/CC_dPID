# 插入分隔符：固定 "\n\n" vs 与标签无关地随机抽取

`run.sh` → `dPID/tests/separator_shift.py`。两臂都开首字母重抽和首尾空白去除，只差训练 collator
的 `insertion_separators`（None = 固定 "\n\n"；mixed = "\n\n"/"\n"/" " 均匀）。
探针对同一批测试样本组合两次，除分隔符外（邮件、位置、模板、大小写）完全相同：
一次独立成段，一次用单个空格嵌进句子。阈值 = 段落视图良性 1% FPR。只统计 email+payload 形式。

## 结果（3 seeds 均值，每 seed 约 57 条恶意 / 1500 条良性）

| 指标 | 固定 "\n\n" | 随机分隔符 |
|---|---|---|
| Recall 段落 → 内嵌 | 0.704 → 0.704 | 0.751 → 0.744 |
| FPR 段落 → 内嵌 | 0.011 → 0.009 | 0.013 → 0.014 |
| PR-AUC 段落 → 内嵌 | 0.600 → 0.607 | 0.603 → 0.584 |
| 恶意 margin 平均变化 | −0.09 | −0.09 |

## 结论

- **没测出效果**：只见过段落插入的模型，在内嵌插入上也没有变差；两臂差异都在 seed 噪声内。
- 也没有代价：随机分隔符不降低段落视图上的性能。
- 局限：玩具 tokenizer 是按词切分的，换行只是多出来的独立 token，词本身不变。
  真实的 mmBERT 用子词 tokenizer，词前是空格还是换行通常会切出**不同的 token**
  （"▁ignore" vs 换行后的 "ignore"），这正是首字母大小写那类问题，而玩具模型复现不了。
  是否真有影响，需要在真实模型上用同样的配对探针测。
